We built REM in Jac and honestly it saved us from writing a ton of stuff we didn't want to write anyway.

The graph is the database. That's not a metaphor. There's no Postgres, no SQLite, no ORM, no migration files. I didn't write a single line of persistence code. Nodes and edges just survive restarts because that's what Jac does. The whole clinical record, every nursing note, device reading, spoken utterance, belief, contradiction, action item, sits in one graph. When I need to know why a resident is on levofloxacin, I follow edges from the belief back to the source episodes. When escalation climbs the chain, the walker just walks clinician nodes linked by edges. All of it is native traversal, no queries to write.

I also never wrote a prompt template. Every LLM call in the project uses `by llm()` on a typed struct. I define the fields I want back, the model fills them, and if it returns something that doesn't match, Jac rejects it at the type level. No JSON parsing, no retry loops, no "please format your response as valid JSON" in the prompt. The consolidation abstract phase fills a flat struct from a cluster of episodes. The reconcile phase fills an enum. The SBAR composition fills a nested struct with the full handoff. Flat stuff goes to a cheap model. The nested SBAR goes to a stronger one. Same mechanism either way. Tests swap in a MockLLM with canned outputs so I can run everything offline without an API key.

Walkers are the other big one. They're graph crawlers, not functions. Consolidation walks from the root to find clusters of related episodes. Escalation walks the clinician chain by rank until someone answers. The whole handoff session lifecycle, creating sessions, attaching transcripts, listing history, is walkers traversing edges. I never wired an endpoint or wrote route handlers. Walkers with `pub` on them auto-register at `/walker/<Name>`. Swagger is free. The graph viewer at `/graph` is free.

The whole thing starts with one command. REST API, Swagger docs, graph viewer, client UI, all from the same process. No Express, no Vite config, no separate frontend repo. The client is `.cl.jac` files that compile to React. I loaded d3-force through the project TOML file. The browser opens a WebSocket to Deepgram directly and streams mic audio without sending bytes through the server.

I didn't write persistence code, endpoint wiring, prompt templates, or output parsers. Those just weren't problems I had to solve.
